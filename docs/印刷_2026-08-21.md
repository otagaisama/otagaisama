## 2. 設計判断とその理由（再提起しない）

### 表は全数同一、可変は裏だけ（06-17・07-20・08-02）
両面印刷で最も怖い「表と裏の中身が食い違う」事故を構造で潰す。表の版が1つで済み、表刷り置きもできる。
両面デジタル（09-17確定）なら機械が表裏対応を保証するため束ごとに表を変える余地はあるが、必要が生じるまで使わない。

### 子QRは1枚ごとに一意（06-17）
共通QRにすると部屋の付け替え履歴（room_transfers）が潰れる。紙のQRは固定、指す部屋が世代交代する（reply_and_claim・08-03確定）。

### 束＝100枚＝1bundle＝1親QR＝1lot（07-12・07-28）
cut-and-stack で面付けエンジンがDBの束順どおりに並べる。物理の山とDBの束が一致していないと、協賛店の親QRが手元にない紙をclaimしてしまう。
400枚でも束運用する（4丁×100シート）。数量は400×m。1山に複数束が積まれる場合は100シートごとにlotが繰り上がる。

### lot_no は `{lot4桁}-{束内position3桁}`（08-02・09-17実装）
家庭用はH接頭辞。旧「バッチ-山（1-1）」「Lot.0001-001」は廃止。create_bundle_v2 が rooms.lot_no に書くため後処理なし。

### 空欄を作らない（08-02）
手書き欄は運営が管理できない印字面になり、半永久で回る紙に乗って巡回する。
家庭用の作成者欄は**印字**（ペンネーム）。印刷屋の協賛なし束の余白は**運営が配布前に判子を押す**ためのもので、受け手に書かせる欄ではない。

### 協賛の見せ方（08-02・09-17）
看板型（協賛／株式会社◯◯）ではなく文型（このカードは下記の協賛により作られました）。主語がカードになり会社は支えた側に回る。
ロゴはベクターPDFをそのまま埋め込む（CMYKのまま通る）。**文字だけの協賛面は見劣りするため作らない**。営業では「文字でもいける」と言うだけ。
TK&Mロゴは「株式会社」の文字を除外して使う（未登記の社名に会社の文字を刷らない）。

### 画像化は採らない（09-16）
「画像化すれば消える」とされた3点（サブセット再生成・β・可変はHelveticaで足りる）は全部 print.html（jsPDF）固有の制約で、ReportLab＋フルTTF埋め込みならそのまま消える。画像化は宿題（350dpiの細線・4色黒・自作ツール）を付け替えるだけ。画像で扱うのは協賛ロゴと家庭用の作成者欄（任意文字・絵文字）のみ。

### β・作成日・罫線は刷らない（09-16／17）
半永久で回る紙にβは数ヶ月で嘘になる（Shippori原本・Helvetica・Zen Kakuにβの字形が無いことも確認）。作成日は lot_no と印刷済み日時で代替できる。0.25mm罫は断裁±1〜2mmで左右非対称が目視で出る。

### 色（09-16／17）
印刷屋はCMYK直指定・黒K100。ロゴ束を含むバッチは4色（1シート1ジョブ）。墨のみの束を1本入れて同紙同機で色比較。家庭用はRGBのまま（トナー）。

### QR（08-02・09-16）
印刷屋22mm・家庭用16mm・ともにECC Q（紙モノはQ推奨・欠損耐性25%）。10mmまで読める実測に対し家庭用16mmは0.432mm/マス、印刷屋22mmは0.595mm/マス。白地は4モジュール分。

### 家庭用の期限と再利用（08-02）
2ヶ月は実装済み。再利用はシステムが既に対応、必要だったのは文言だけ。「受け取ったあとも繰り返し使えます」は不採用（取り込まずに紙だけ回してよいと読める）→「メッセージ取り込み後、繰り返し使用できます」。

### 印刷ゲート（08-12）
本番束は印刷直前に新規生成し、既存在庫を流用しない。旧文字（g i l o s z）を含む short_id が紙に乗らないようにする。エンジンは旧文字を検出したら止まる。

### 印刷済み警告（07-10）
シート単位（bundles.printed_at）。PDF生成と直接印刷の両方で警告＋記録。誤記録の実害（余計な警告1回）＜記録漏れの実害（重複ばらまき）。

## 4. 教訓（忘れると静かに壊れる）

1. **fonts_subset.js はカード文言の字だけ**。文言を変えたら再生成しないと豆腐になる。原本は Google Fonts の Shippori Mincho（印刷屋エンジンと同じ）。文字リストは print.html の `TXT` 定数から拾う
2. **HTML面（buildCard／CSS）とPDF面（drawPdfCard）は別コードパス**。片方だけ直すとプレビューと紙が食い違う
3. jsPDF内蔵フォント（Helvetica等）はWinAnsi範囲のみ。ギリシャ文字・絵文字は出ない。任意文字はcanvas画像で貼る
4. 発行と同時にclaimするなら rooms 側だけでなく bundles 側（claimed_by／claimed_at）にも書く。片側だけだと bundles 基準のRPCが空振りする
5. **印刷屋の入稿データは print.html から出ない**。HANDOFFの「print.html の旧名称＝入稿ブロッカー」は誤りだった（09-16訂正）
6. HANDOFFの行番号は差し替えのたびにずれる。行番号ではなく文字列で探す
7. 印刷所が「返信待ち」でも、入稿データが無ければ止めているのはこちら（08-21）
8. 本物の short_id を含む manifest・PDF・照合CSV、bundles.parent_token は公開リポジトリに置かない。ダミーIDのみ可
9. GitHub Web の Upload でファイル名に空白が混ざると同名の別ファイルができる。上げたら tarball で全体を照合する
