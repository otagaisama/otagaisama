## 確定事項（再提起しない）

- **作成日時は刷らない**（2026-09-17変更。旧：刷る）
  試作段階の「いつの印刷物か分からない」問題は lot_no と mypage の印刷済み日時で解決した。
  紙に日付があると半永久で回るカードが古く見える方が実害。
- **有効期限は刷らない**
  起点が親QR有効化のため、印刷時点で期限日が確定しない。ロットで辿れるので不要。
- **lot_no は必須**（辿る鍵。家庭用はH接頭辞）
- **家庭用に親QRは無い**。生成＝そのままclaimで所有者が自分になる
- **「半永久」の定義に期限は最初から含まれる**（2026-05-21・TAKA発
  「汚れ、破損、期限までとする」）。1回使い捨てではなく何度も回せる、の意。
- **英語1行は入れない**（2026-08-02）。肩書の `HeartCloak Project` は名称であり英文ではない。
- **βは刷らない**（2026-09-16）。半永久で回る紙に「β」は数ヶ月で嘘になる。
  Shippori Mincho 原本・Helvetica・Zen Kaku のいずれにも β の字形が無いことも確認済み。
  画面側（フッタ・meta・吹き出し）のβ表記はそのまま。
- **表に可変データを置かない**（下記「面付けの安全性」）
- **使用済みカードは表裏とも黒**（2026-09-17）。裏だけ黒だと表から有効なカードに見える。

## 未決だった3点の決着（2026-08-02）

### ① 家庭用に期限を設けるか → **2ヶ月で実装済みだった**

画面に「カードの使用期限は、つくった日から2ヶ月です」と表示（EXPIRE_MONTHS 定数）。

**期限ありの利点**：空部屋対策／印刷するくせづけ／「永遠に使える」を約束せずに済む
**期限なしの利点**：利便性／一人20枚上限で代替できる
**非対称性**：印刷屋カードはユーザーにとって無償。家庭用は自分の紙・インクで刷るため
期限で使えなくなると「金を払った紙が死んだ」になる。
**中間案（未実装）**：期限が来たら刷り直しを促す。short_idは殺さず mypage で「期限切れ・再発行しますか」。

### ② 再利用を許可するか → **システムは既に対応済み。案内文言だけの問題だった**

返信投稿時に `reply_and_claim` が走り、同じ short_id が新しい部屋に付け替わる（2026-08-03コードで確定。
lot_no 引き継ぎも 2026-08-07 修正済み）。止まるのは short_id が抜けた抜け殻部屋／お役目終了／束の期限切れ。
案内文言はカード面の「メッセージ取り込み後、繰り返し使用できます」に反映済み。
**「受け取ったあとも繰り返し使えます」は不採用**（2026-09-17）：スマホで取り込まずに紙だけ次へ回してよい、と読めるため。
紙質には関与しない。厚紙にするかは刷る人が決める。

### ③ 片面か両面か → **両面で確定・2026-09-17実装完了**

決め手は「表からQRと説明を追い出せる」こと。コンビニのマルチコピー機の自動両面（長辺とじ）で
表裏が正しく重なることは H0002 で実地確認済み。

## カード面の内容（2026-09-17凍結・印刷屋と共通）

### 表（固定・10枚とも同一）

```
HeartCloak Project                 ← 左上・金・Zen Kaku 7.5pt
（中央）
こころづて                          ← Shippori Mincho Bold 16pt・墨
こころを預かり届けます               ← Shippori 7.5pt・墨（朱は目立ちすぎるため不採用・2026-09-17）
ふとした時に、こころを残してみませんか？ ← Shippori 6.5pt・墨70%
```

「残す」は表2行目の「預かり届けます」と対になる語（書き手が置く→こちらが運ぶ）。
「伝える」は相手に向かう語で預かる側の文言と噛み合わないため不採用。`？` は全角。

### 裏（左列＝可変／右列＝固定）

```
[QR 16mm・白地2mm]   QRからメッセージを受け取ってください。
 short_id            読めないときは heartcloak.com へ。
 lot_no（金・小）     このカードはメッセージ取り込み後、
                     繰り返し使用できます。
                     ───────（金罫）
                     このカードは下記の方が作成しました。
                     [判子] ペンネーム全文
                     heartcloak.com
```

- 判子＝受け取り画面の `signHanko` と同じ意匠（先頭2文字・朱の丸・白抜き）
- ペンネーム＝ログインユーザーの `user_metadata.pen_name`（無ければ name → メールの@前 → 匿名）
- 判子＋ペンネームは **ブラウザの canvas で画像化（約600dpi）して PDF に貼る**。任意の文字・絵文字が
  入るため埋め込みフォント（Shippori サブセット）では出せない。家庭用は原寸100%のトナー印刷なので
  この1要素だけ画像で問題ない。canvas が使えない場合は英字だけ Helvetica で出す保険つき
- 「作成していただきました」は不採用（自分で刷る自分のカードに敬語になる）
- 印刷屋用は同じ位置が**協賛欄**（金罫→「このカードは下記の協賛により作られました」→ロゴ 50×7mm）。
  協賛なし束は右下を約50×18mm空け、URLを左列 lot 枠の下に移す（運営が後から判子を押す余地）

**表記の確定**
- `HeartCloak Project`（半角スペース区切り）。ハイフン結合・詰め書きは不採用。綴りは **cloak**
- 日本語名は「こころづて」単独。「こころづてプロジェクト」等の複合形は使わない

**lot_no の見せ方**：家庭用は金・小さめ（照合用途は mypage の印刷済み日時と lot 一覧で足りる）。
印刷屋用は金枠バッジ＋墨文字（2026-08-02の判断どおり）。

## QRの不可侵条件（意匠で崩してはいけない）

- 白地に黒・単色。反転・背景写真への重ね・色付けは不可
- クワイエットゾーン4モジュール分の白地。文字・罫線・背景色を置かない
- トリム端から5mm以上内側

### 家庭用のQR仕様（2026-08-02確定・2026-09-17実装）

| 項目 | 値 |
|---|---|
| QR本体 | **16mm** |
| クワイエットゾーン | **2mm**（規定1.94mm以上。白地20mm角） |
| ECCレベル | **Q** |
| モジュール数 | 37×37（v5・URL47文字） |
| 1マス | 0.432mm |

**16mmにした理由**：実測で10mm（1マス0.303mm）まで読めている／22mmは印刷屋の裏面レイアウト由来／
本体を小さくして白地を規定どおり取る方が読み取りは強い。
**ECC Q にした理由**：紙モノでQ推奨／欠損耐性15%→25%／半永久で回る＝汚れ・折れは既知条件。

### QRサイズ実測（2026-07-28）
- 家庭用プリンタ＋型落ちiPhoneで**10mmまで読取成功**（1マス0.303mm）
- 残：ケント180kgでの再検証は印刷屋バッチ0001の現物で行う

## 面付けの安全性（設計判断・2026-08-02）

**表に可変データを置かない。可変データは全て裏に集める。**
面付けの向きを間違えてもカードが死なない／表の版が1つで済む／裏だけ刷り替えれば別ロットが作れる。

**裏面ミラー（家庭用）**：長辺とじで裏返すと左右が入れ替わるため、**裏面の列を左右入れ替えて配置**
（print.html `cellRoomIndex`）。表が固定内容なので必須ではなく、lot_no の並びを揃える保険。
**印刷屋はミラー無し**（冠野K3：版下は同方向でUP、刷版で調整・両面デジタル）。

**制約**：表に可変を置けない＝作成者名は裏。2026-09-17 に裏右下の作成者欄として実装。
表を束ごとに変える余地は印刷屋（両面デジタル）にはあるが、今回は使わない。

## 空欄を作らない原則（2026-08-02確定・再提起しない）

作成者名などを**空欄で刷って手書きさせる案は却下**。運営が管理できない印字面を作ることになるため。
家庭用の作成者欄は**印字**（ペンネーム）であり空欄ではない。
印刷屋の協賛なし束の余白は、**運営が配布前に判子を押す**ための余地であり、受け取った人に書かせる欄ではない。

## 印刷まわりの実装事実（2026-09-17更新）

- print.html は**2ページPDF**（1ページ目＝表・2ページ目＝裏）を出力。画面プレビューも表裏を縦に並べる。
  「この画面からそのまま印刷」も2ページ出る（`page-break-after`）
- ファイル名は `kokorozute_H0004.pdf`
- QRのURLは `https://heartcloak.com/receive.html?room=<short_id>`（直焼き・47文字）
- 発行RPCは `create_my_bundle`（ログイン必須）。発行時点で所有者が確定する
- 印刷屋用は別エンジン（tools/print_engine/）。print.html から入稿データは出ない

### フォントの制約（2026-08-02発覚／2026-09-17再生成）

`fonts_subset.js` は**カード面の文言に使う文字だけを収録したサブセット**。文言を変えると豆腐（□）になる。
- 2026-09-17 に新文言で再生成（Regular 153字／Bold 103字・69KB。pyftsubset `--no-hinting --layout-features=`）
- 原本は Google Fonts の Shippori Mincho Regular/Bold（OFL）。印刷屋エンジンと同じ原本
- **カード文言を変更したら必ず fonts_subset.js を再生成する**（手順は tools/print_engine/README_engine.md と
  同じ原本を使う。文字リストは print.html の `TXT` 定数から拾う）
- β は刷らないため、ラテン用フォントの追加は不要になった

## 印刷屋への流用可否（2026-08-02整理／2026-09-17決着）

**流用したもの**：文言／情報の階層（表＝こころ／裏＝機能＋協賛）／書体と色のトークン（クリーム地は家庭用のみ）／
番号の見せ方／表に可変データを置かない構造

**別にしたもの**：QRサイズ（16／22mm）／面付け・トンボ・塗り足し（印刷屋のみ）／色空間（印刷屋はCMYK直指定）／
裏面ミラー（家庭用のみ）／協賛欄と作成者欄

**内枠罫（旧・未決）→ 廃止で決着（2026-09-16）**。断裁±1〜2mmで左右非対称が目視で出るため。
**協賛欄の形式（旧・未決）→ 決着（2026-09-17）**：ロゴはベクターPDF（CMYK）をそのまま埋め込む（TK&Mで実証）。
文字だけの協賛面は見劣りするため作らない（営業では「文字でもいける」と言うだけ）。
詳細は HANDOFF「印刷仕様の決定（2026-09-16／17）」と tools/print_engine/README_engine.md。
