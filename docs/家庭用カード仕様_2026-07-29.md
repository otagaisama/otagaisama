## 確定事項（再提起しない）

- **作成日時は刷る**
  理由＝試作段階で手元の印刷物がいつのものか判別できなかった実害があった。
  「在庫が古く見える」懸念は却下（2年も寝ない）。本番で外すかは最終段階で再検討
- **有効期限は刷らない**
  起点が親QR有効化のため、印刷時点で期限日が確定しない。物理的に印字できない。
  ロットで辿れるので不要。※システムとしての有効期限は別途存在する
- **lot_no は必須**（辿る鍵。家庭用はH接頭辞）
- **家庭用に親QRは無い**。生成＝そのままclaimで所有者が自分になる
- **「半永久」の定義に期限は最初から含まれる**（2026-05-21・TAKA発
  「汚れ、破損、期限までとする」）。1回使い捨てではなく何度も回せる、の意。
  無期限という意味ではないので、期限の議論と矛盾しない
- **英語1行は入れない**（2026-08-02）。家庭用は配る相手が日本語話者に限られるため。
  インバウンド配布インフラ構想が動く場合は印刷屋側で別途判断する

## 未決だった3点の決着（2026-08-02）

### ① 家庭用に期限を設けるか → **2ヶ月で実装済みだった**

デザイン検討中に print.html の実装を読んで発覚。
画面に「カードの使用期限は、つくった日から2ヶ月です」と既に表示されている
（EXPIRE_MONTHS 定数）。**未決ではなく実装済み**だった。

以下は未決時代に整理した判断材料。値を変える議論をする場合の下敷きとして残す。

**期限ありの利点**
- 空部屋対策
- **印刷するくせづけ** … 期限があると刷り直す→配る→回る
- 「永遠に使える」を約束せずに済む（サービス継続の保証は誰にもできない）

**期限なしの利点**
- 利便性／一人20枚上限で代替できる（在庫総量を絞れば空部屋も構造的に減る）

**非対称性**
スポンサー用カードはユーザーにとって無償。期限で死んでも痛みがない。
家庭用は自分の紙・インク・時間で刷っている。期限で使えなくなると
「金を払った紙が死んだ」になる。同じ期限でも受け取られ方が違う。

**中間案（未実装）**：期限が来たら死ぬのではなく刷り直しを促す。short_idは殺さず、
mypageで「期限切れ・再発行しますか」を出す。空部屋は祈りの木に還して回収し、
器は作り直せる。

### ② 再利用を許可するか → **システムは既に対応済み。案内文言だけの問題だった**

receive.html の実装を確認（2026-08-02）。
返信投稿時に `reply_and_claim` が走り、**同じ short_id が新しい部屋に付け替わる**。
画面にも「返信とともに、このカードのバトンはあなたに渡りました／
今度はあなたが送る側です」と表示される。回数上限はフロント側に見当たらない。

止まるのは3条件のみ。
- short_id が抜けた抜け殻部屋
- お役目終了されたカード
- 束の期限切れ（**家庭用は束がないため無関係**）

つまり**新規実装は不要**。必要だったのは以下2つだけ。
- 厚紙で刷る（普通紙では2回目でヨレる）
- 案内文言を「使い切り」から「繰り返し使えます」に変える → **カード面に反映済み**

**未確認**：`reply_and_claim` のSQL本体は未読。世代カウンタに上限が
仕込まれている可能性はゼロではない（バトン回数表示があるのでカウンタ自体は存在する。
ただしカウンタ＝上限ではない）。**実カードで2世代目を回せば確定する**。

**紙質には関与しない**（2026-08-02確定）。厚紙にするかは刷る人が決める。
裏面地紋を任意とした②の方針と同じ構造。

### ③ 片面か両面か → **両面で確定**

決め手は「表からQRと説明を追い出せる」こと。片面では右20mm弱をQRブロックに
取られるが、両面なら表が91×55mm丸ごと空く。クウの絵を入れる余地もここに生まれる。

**面の割り振り（確定）**

| 面 | 内容 |
|---|---|
| 表 | HeartCloak Project β（左上・小）／こころづて／こころを預かり届けます／下半分は余白 |
| 裏 | QR＋short_id＋lot_noバッジ（左）／説明3行・協賛・URL・作成日時（右） |

**表に可変データを置かない**という設計判断が効いている（詳細は下記「面付けの安全性」）。

コンビニのマルチコピー機なら自動両面が使えるため、
「家庭用プリンタの両面は位置がズレる」という当初の懸念は回避できる。

## カード面の内容（2026-08-02確定）

### 表

```
HeartCloak Project β        ← 左上・金・小
（中央）
こころづて                   ← 明朝・大
こころを預かり届けます        ← 朱
（下半分は余白）
```

### 裏

```
[QR 16mm]          QRからカードを受け取ってください。
 short_id          読めないときは heartcloak.com へ。
[lot_no 金枠]      この名刺は繰り返し使えます。
                   ───────
                   このカードは下記の協賛により作られました
                   株式会社◯◯
                   heartcloak.com　2026.08.01
```

**表記の確定**
- `HeartCloak Project`（半角スペース区切り）。ハイフン結合・詰め書きは不採用。
  理由＝ハイフンはURL/ファイル名の記法に見える。`Project` は種別を表す語なので
  離すのが自然（Manhattan Project と同じ）。ロゴで詰めたい時に字間調整できる利点もある
- 綴りは **cloak**（clockではない）

**協賛の表記（2026-08-02確定）**
看板型ではなく文型を採用する。

```
（不採用）協　賛 ／ 株式会社◯◯
（採用）  このカードは下記の協賛により作られました ／ 株式会社◯◯
```

主語が「このカード」になり、会社が支えた側として後ろに回る。
欄を増やさないため空欄問題（後述）も発生しない。

**lot_no の見せ方（2026-08-02修正）**
初案の「金・11px相当」は視認性が低く却下。以下に修正した。
- 文字を**金→墨**にする（枠だけ金）
- サイズを short_id より**大きく**する
- 金枠バッジの形を mypage 側（UI調整①）と揃える

理由＝lot_no の用途は**名刺照合**。手元の紙と mypage の一覧を突き合わせるための
番号であり、照合するのは lot_no の方。紙が読めなければ画面を直したことの意味が消える。
モノクロ印刷時も枠がグレーに落ちるだけで文字は墨のまま残る。

## QRの不可侵条件（意匠で崩してはいけない）

- 白地に黒・単色。反転・背景写真への重ね・色付けは不可
- クワイエットゾーン4モジュール分の白地。文字・罫線・背景色を置かない
- トリム端から5mm以上内側（4丁付け断裁の±1〜2mmズレ対策）

### 家庭用のQR仕様（2026-08-02確定）

| 項目 | 値 |
|---|---|
| QR本体 | **16mm** |
| クワイエットゾーン | **1.94mm**（16÷37×4） |
| 実効サイズ | 19.88mm四方 |
| ECCレベル | **Q** |
| モジュール数 | 37×37（v5） |
| 1マス | 0.432mm |

**16mmにした理由**
- 実測で10mm（1マス0.303mm）まで読めている。16mmはその1.6倍で裏付けの範囲内
- 22mmは印刷屋の両面レイアウト（裏面QRブロック33mm確保）から来た数字であり、
  家庭用に機械的に持ち込む必然性がない
- 小さい方が文字スペースが広く、意匠上も収まりがよい（TAKA判断）
- **本体を小さくして白地を規定どおり取る方が、同じ面積で読み取りは強くなる**。
  22mmは本体だけで「16mm＋白地」の全体より大きい

**ECC Q にした理由**
- 実装は M だった。紙モノでQ推奨という指針との齟齬を解消
- Q にすると v4(33×33)→v5(37×37) に繰り上がり1マスが11%細かくなるが、
  0.432mm は実測下限0.303mm に対して43%の余裕がある。600dpiで1マス約10ドット
- 欠損耐性 15%→25%。カードが半永久で回る＝汚れ・折れは確実に起きる条件なので、
  「起きてから対応」ではなく既知条件への対応にあたる
- コストは `qrcode(0,'M')` → `'Q'` の1文字。取引として得

**変更容易性**：ECCもサイズも print.html の定数変更で済む。
戻せないのは刷って配った紙だけ。家庭用は少部数のため試して直せる。
**印刷屋の2,000枚は刷ったら戻れない**ので、家庭用の実地結果を判断材料にする。

### QRサイズ実測（2026-07-28）

- 家庭用プリンタ＋型落ちiPhoneで**10mmまで読取成功**（1マス0.303mm）
- 危険域とされる0.4mm/マスを大きく下回っても読める＝**基準値は実態より保守的**
- 残：ケント180kg入手後に本番用紙で再検証（家庭用紙とにじみ傾向が違う）

### 検証用ファイル qr-size-test.html（使い捨て・リポジトリ未収録）

- A4に91×55mmを2列5行＝10枚。19mm〜10mmを1mm刻みで面付けしPDF生成
- **Supabaseに一切触らない独立ファイル**。何度PDFを出してもDBは汚れない
- URL文字数を47文字で固定→全カード33×33モジュールに統一。変数は物理サイズのみ
- クワイエットゾーンもサイズに比例させている（固定にすると変数が2つになる）
- 各QRに `qt19mm`〜`qt10mm` の異なるIDを埋め込み、
  読み取ったURL末尾でどのサイズが読めたか判別できる（隣接QRの誤読を防ぐ）
- 印刷時は**拡大縮小なし（100%）**。ここを間違えるとテストが無意味になる
- 再作成が必要な場合はこの仕様どおり作り直せばよい

## 面付けの安全性（設計判断・2026-08-02）

**表に可変データを置かない。可変データは全て裏に集める。**

TAKAの設計判断。両面印刷で最も怖い「表と裏の中身が食い違う」事故を
構造的に潰している。印刷業界のセオリーと一致する。

**効いている点**
- 面付けの向きを間違えてもカードが死なない（表は10枚とも同一内容のため、
  どの表とどの裏が組んでも正しいカードになる）
- 表の版が1つで済む
- 裏だけ刷り替えれば別ロットが作れる
- 表が完全な一枚絵になり、意匠の余地が生まれる
- **印刷屋の2,000枚でも同じ強度が効く**。両面の見当が多少ズレても
  中身の取り違えは起きない

**裏面ミラー**：長辺とじで裏返すと左右が入れ替わるため、裏面の列順を
あらかじめ反転させておく。ただし上記のとおり表が固定内容のため、
**今の構成ではミラーは必須ではなく、lot_no の並び順を揃えるための保険**。

**制約**：表に可変を置けない＝作成者名などを表に入れられない。
入れるなら裏だが、裏は既に埋まっている。
**逃げ道は「裏の固定要素（説明3行など）を表に移す」**こと。
ただし表が一枚絵でなくなるため、必要が生じるまで動かさない。
詳細は docs/個人名入りカード構想_2026-08-02.md

## 空欄を作らない原則（2026-08-02確定・再提起しない）

作成者名などを**空欄で刷って手書きさせる案は却下**。

理由＝**運営が管理できない印字面を作ることになる**。判子や書き込みで
運営の意図しないものが乗り、カードは半永久で回るためそれが延々巡回する。
枠を用意した側が結果的に場を貸したことになる。

家庭用も同じ危険はあるが枚数制限で抑えられる。試作段階で空欄を検討したのは
スポンサー不在で名刺を無駄にしたくなかったためであり、その場合も渡す先は
信用できる店舗に限る前提だった。

## 印刷まわりの実装事実

- print.html はHTTPS専用APIを使っていないため http でも動作する
- print.html は**PDF直接出力に既に対応**（「PDFをつくる（保存）」ボタン）。
  コンビニのネットプリント登録を前提とした案内も画面に入っている
- QRのURLは `https://heartcloak.com/receive.html?room=<short_id>`（直焼き・確定）
- URLは64→47文字に短縮。ECC M なら33×33、**ECC Q なら37×37**
- 発行RPCは `create_my_bundle`（ログイン必須）。
  **発行時点で所有者が確定する**＝家庭用に未claim状態は存在しない。
  owner_user_id が NULL になるのは印刷屋ルートの未claim束在庫のみ

### フォントの制約（2026-08-02発覚・重要）

`fonts_subset.js` は**カード面の文言に使う文字だけを収録したサブセット**。
文言を変えると豆腐（□）になる。

2026-08-02時点の実測：新文言に対し**日本語26字が不足**していた
（協・賛・株・式・会・社・預・繰・返・下・記・作・刺・名 など）。

- **カード文言を変更したら必ず fonts_subset.js を再生成する**
- 再生成は pyftsubset（fontTools）で Shippori Mincho 原本から作る
- **`β` は Shippori Mincho に収録がない**（ギリシャ文字のため）。
  ラテン用に別フォントを併用する必要がある。
  `HeartCloak Project β` を刷る以上、この対処は必須

## 印刷屋への流用可否（2026-08-02整理）

**そのまま流用できるもの**
- 文言（説明3行、協賛の文型、こころを預かり届けます）
- 情報の階層（表＝こころ／裏＝機能＋協賛）
- 書体と色のトークン（Shippori Mincho・墨・金・朱・クリーム地）
- 番号の見せ方（lot_no を主・short_id を従、金枠バッジで mypage と対応）
- **表に可変データを置かない構造**

**流用できないもの**
- QRサイズ（家庭16mm／印刷屋22mm で系統分け）
- 面付け・トンボ・塗り足し（冠野の指示待ち項目が残る）
- カラー/モノクロの前提（印刷屋はフルカラー前提）
- 長辺とじの結論（断裁機は別物）

**印刷屋で弱点になるもの（未決）**
外周から2.2mm内側に0.25mmの内枠罫を引いている。家庭用は自分で切るので
ズレても自己責任だが、**印刷屋は断裁機で切るため誤差±0.5〜1mmが出る**。
フチのある意匠はこのズレが左右非対称になって目に見える。

回避策は3つ。①フチをやめる ②フチを内側に寄せる（4〜5mm）
③そのまま行って多少のズレは味とする。**未決**。

**協賛欄の形式（未決）**
現在はテキスト前提だが、実際のスポンサーはロゴ画像で来る可能性が高い。
ロゴはアスペクト比がばらばらのため、テキスト前提で枠を決めると組み直しになる。
**スポンサーが実在するまで確定できない**。試作の社名表示は位置と大きさ感を
掴むためのダミー。
