## 系統の整理（家庭用とスポンサー用は別物）

| | 家庭用（じぶん印刷） | スポンサー用（印刷屋） |
|---|---|---|
| 刷る人 | 自分 | 冠野栄興社 |
| lot_no | **H**0001-047（H接頭辞） | 0001-047 |
| 面 | 片面（費用抑制） | 両面 |
| 面付け | A4に91×55mmを2列5行＝10枚 | 4丁付け・2,000枚 |
| 束 | H0001束（10枚） | 100枚＝1山＝1bundle＝1親QR |
| 親QR | **なし**（生成＝self claim） | あり（店主がスキャンして有効化） |
| スポンサー | 付かない | 付く |
| 期限 | **なし**（未決・下記①） | あり（有効化から3ヶ月＋書きかけ30日猶予） |

HANDOFFの「両面」は印刷屋の実行指示書v1.3に限った記述。
print.html が単面（drawPdfCard 1関数・addPage なし）なのは**仕様どおり**でギャップではない。

## 確定事項（再提起しない）

- **作成日時は刷る**
  理由＝試作段階で手元の印刷物がいつのものか判別できなかった実害があった。
  「在庫が古く見える」懸念は却下（2年も寝ない）。本番で外すかは最終段階で再検討
- **有効期限は刷らない**
  起点が親QR有効化のため、印刷時点で期限日が確定しない。物理的に印字できない。
  ロットで辿れるので不要。※システムとしての有効期限はスポンサー用に別途存在する
- **lot_no は必須**（辿る鍵。家庭用はH接頭辞）
- **家庭用は片面**（費用抑制。ただし下記③で再検討の余地あり）
- **家庭用に親QRは無い**。生成＝そのままclaimで所有者が自分になる
- **「半永久」の定義に期限は最初から含まれる**（2026-05-21・TAKA発
  「汚れ、破損、期限までとする」）。1回使い捨てではなく何度も回せる、の意。
  無期限という意味ではないので、期限の議論と矛盾しない

## 未決（デザインチャットで詰める）

### ① 家庭用に期限を設けるか  ※システム側が一意に決める必要がある

**あり**
- 空部屋対策
- **印刷するくせづけ** … 期限があると刷り直す→配る→回る
- 「永遠に使える」を約束せずに済む（サービス継続の保証は誰にもできない）

**なし**
- 利便性
- 一人20枚上限で代替できる（在庫総量を絞れば空部屋も構造的に減る）

**判断材料（非対称性）**
スポンサー用カードはユーザーにとって無償。期限で死んでも痛みがない。
家庭用は自分の紙・インク・時間で刷っている。期限で使えなくなると
「金を払った紙が死んだ」になる。同じ期限でも受け取られ方が違う。

**中間案**：期限が来たら死ぬのではなく刷り直しを促す。short_idは殺さず、
mypageで「期限切れ・再発行しますか」を出す。空部屋は祈りの木に還して回収し、
器は作り直せる。

**補足**：現状は使い切り運用のため、余った白紙は手持ちタブの
「名刺破棄」（discard_card・実装済み）で本人が整理できる。
所有者が自分である限り、辿れなくなる状態は発生しない。

### ② 再利用を許可するか

現在は使い切り（理由＝普通紙は使い回しにくい）。
ただし厚紙で刷る人もいるため、許可してもよいと考えている。

**許可する場合の方向**：**裏面の地紋は刷る人の任意**とする。
「使い回すなら裏も刷ってね」と案内するだけ。プロジェクト側は選択肢を出し、
判断は刷る人に委ねる（練習場思想と整合）。

**注意（①③と連動する）**：再利用を開くと白紙裏面のリスクが上がる。
同じ紙が何人もの手を渡るようになると、裏面が「誰でも使える広告スペース」になる。
回れば回るほど価値が上がる媒体のため、動機も強まる。

### ③ 片面か両面か

- **片面** … 子供が裏に落書きできる余地がある
- **両面** … 個人のIDペンネームを入れ、**カード作成の協賛者**とする

**判断材料**
- 落書きと宣伝は同じ空白を奪い合う。意匠では区別できない。
  分けられるのは「誰の手に渡るか」だけ → **②の再利用可否とセットで決まる**
- 家庭用プリンタの両面は位置がズレるし普通紙は裏写りする。
  厚紙前提なら解決するが「普通紙で気軽に」が消える
- ペンネーム側は軽い。その人の全カードで同一内容のため
  1枚ごとの可変データにならず、面付けの負荷はほぼゼロ
- 「個人がカード作成の協賛者になる」は、確定事項
  「個人スポンサーもプレイヤー側でなくスポンサー側」と整合する。
  ただし「協賛」を収益の意味と自称の意味で二重に使うと営業時に濁るため語彙整理が要る

**②③は選択制にできる（①はできない）**
片面/両面は print.html に「裏面も刷る」チェックボックスを置けば済む。
落書き派は片面、名前を入れたい人は両面。地紋任意と同じ構造で排他ではない。
期限だけはシステム側が一意に決める必要がある。

## QRの不可侵条件（意匠で崩してはいけない）

- 白地に黒・単色。反転・背景写真への重ね・色付けは不可
- クワイエットゾーン4モジュール分の白地。文字・罫線・背景色を置かない
- トリム端から5mm以上内側（4丁付け断裁の±1〜2mmズレ対策）
- **QR実寸は22mm確定。ただし print.html の実装は19mm＝実装漏れ**
  （クワイエットゾーンも実装1mm／規定は約2.7mm）

### QRサイズ実測（2026-07-28）

- 家庭用プリンタ＋型落ちiPhoneで**10mmまで読取成功**（1マス0.303mm）
- 危険域とされる0.4mm/マスを大きく下回っても読める＝**基準値は実態より保守的**
- **採用値は22mmのまま据え置く**。余裕はインクのにじみ・紙の折れ・暗所・手ブレ・
  低性能端末を吸収する保険。読める最小値を採ってはいけない
- デザイン都合で縮める場合、**16〜19mmまでは実測上の裏付けあり**
- 残：ケント180kg入手後に本番用紙で再検証（家庭用紙とにじみ傾向が違う）

### 検証用ファイル qr-size-test.html（使い捨て・リポジトリ未収録）

- A4に91×55mmを2列5行＝10枚。19mm〜10mmを1mm刻みで面付けしPDF生成
- **Supabaseに一切触らない独立ファイル**。何度PDFを出してもDBは汚れない
- URL文字数を47文字で固定→全カード33×33モジュールに統一。変数は物理サイズのみ
- クワイエットゾーンもサイズに比例させている（固定にすると変数が2つになる）
- 各QRに `qt19mm`〜`qt10mm` の異なるIDを埋め込み、
  読み取ったURL末尾でどのサイズが読めたか判別できる（隣接QRの誤読を防ぐ）
- 印刷時は**拡大縮小なし（100%）**。ここを間違えるとテストが無意味になる
- 再作成が必要な場合はこの仕様どおり作り直せばよい

## 印刷まわりの実装事実

- print.html はHTTPS専用APIを使っていないため http でも動作する
- QRのURLは `https://heartcloak.com/receive.html?room=<short_id>`（直焼き・確定）
- URLは64→47文字に短縮され、QRは37×37→**33×33モジュール**になった
- 22mm＝1マス0.667mm という確定値は、この33モジュールを前提にした数字
