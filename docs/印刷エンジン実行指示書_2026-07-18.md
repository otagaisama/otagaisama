# 印刷エンジン実行指示書 v1.3（400枚バッチ×5回・4丁付け・確定版）
出所: TAKA設計・Claude（Fable）文書化 ／ 初版: 2026-07-18 ／ 最終更新: 2026-07-19
実装: 別チャット（Sonnet／Claude Code）。判断余地なし・以下のとおり作る。

## 方針
400枚バッチを5回で計2,000枚。全バッチ同一設定。
束100枚=1bundle=親QR1通の確定事項を維持。

## 確定仕様
- カード: 91×55mm・両面（表デザイン＋裏QR）※6/27テスト現物と同サイズ
- 面付け: A4に4丁付け（2列×2行・余白は裁断マージン）
  1バッチ=400枚=100シート=両面200ページ
- cut-and-stack: バッチ内カード番号c(1..400)
  シートn = ((c-1) mod 100) + 1 ／ 面位置k = floor((c-1) / 100)（k=0..3）
  → 裁断後、4つの山がそれぞれ連番100枚
- 束: 山＝束。1山100枚=1束=1bundle=親QR1通。1バッチ=4束。
  合紙・数え直し・重ね直しすべて不要
- 全体: 5バッチ×4束=20束=2,000枚=親QR20通
- lot_no採番: 「バッチ-山」形式。第1バッチ=「1-1」〜「1-4」…第5バッチ=「5-1」〜「5-4」
  ※「H」始まりは自家印刷用に予約済みのため使用禁止
- bundle対応: バッチp・山q = バッチ内カード(q-1)*100+1〜q*100

## 技術
- jsPDF＋qrcode-generator（QRは必ずベクター直描画・画像貼り禁止）
- フォント: Shippori Minchoサブセット（fonts_subset.js・66KB）
- 裁断線: 現print.html踏襲（0.15mm破線）
- 出力: 1バッチ=1PDF（200ページ）。jsPDFのメモリが苦しければ表裏で
  2ファイル分割可（表100p＋裏100p）。ファイル名にバッチ番号
- 裏面の面付け: フリップ軸をパラメータ化（horizontal/vertical）→K3確定後に値を固定
- パラメータ（既定値固定）: N=400, F=4丁, B=100枚/束
- データ源: create_bundle系RPCをバッチごとに4回→各100枚のshort_id/URL取得
- 生成手順: ①バッチ全400件をJSONマニフェスト書き出し ②欠番・重複ゼロ照合
  ③合格後にPDF生成 ④lot_no4件をbundles.lot_idへ記入

## 冠野変数（返信待ち・確定後に記入）

- K4: 400枚単位×5回の分割発注と2,000枚一括の単価差 → 未（参考として）
