# 印刷エンジン実行指示書 v1.4（400×m枚・4丁付け・実装済み）
出所: TAKA設計・Claude（Fable）文書化 ／ 初版: 2026-07-18 ／ v1.3: 2026-07-24 ／ **v1.4: 2026-09-18**
実装: **完了**（2026-09-17・tools/print_engine/card_engine.py v0.8）。本書は運用手順と確定仕様の正。
v1.3 との差分は末尾「v1.3からの変更」。

## 方針
- 発注単位は **400×m 枚**（4丁付け×100シート単位。m=1〜5、最大2,000）。10丁は次回以降に別途
- **束100枚＝1lot＝1bundle＝親QR1通** を維持。協賛は束ごとに変えられる（束の中は同一）
- **表は全数同一**（表に可変データを置かない＝表裏の取り違えが起きない）。裏だけが可変
- 生成は ReportLab（Python）。print.html（家庭用・jsPDF）から入稿データは出ない

## 確定仕様
- カード: 91×55mm・両面。紙: ケント 四六判180kg（非コート）・表面加工なし
- 面付け: A4横（297×210）に4丁付け（2列×2行）を中央配置。塗り足し3mm分の余裕＋コーナートンボ＋
  センタートンボ。余白は左右48mm・上下41mm（断ち代として十分）
- 地色: 刷らない（紙白）→ ベタ無し＝塗り足し不要（冠野「ベタ刷りなら必要」の裏返し）。3mm分は入れてある
- 裏面ミラー: **無し**（冠野K3: 版下は同方向でUP、刷版で調整。両面デジタル）。config.sheet.mirror_back で切替可
- cut-and-stack: カード番号 c(1..N)、B＝1山の枚数（100×m）
  シートn = ((c-1) mod B)+1 ／ 面位置k = floor((c-1)/B)（k=0:左上 1:右上 2:左下 3:右下）
  → 断裁後、4つの山がそれぞれ連番。山の中は100シートごとに lot が繰り上がる
- **lot_no採番: `{lot4桁}-{束内position3桁}`**（例 0001-047）。lot は create_bundle_v2 の p_lot_id、
  position は rooms.position。**関数が rooms.lot_no に書く**ので後処理なし。
  「H」始まりは家庭用に予約済みのため使用禁止。旧「バッチ-山」「Lot.0001-001」形式は廃止
- 束↔山: 山k の j 本目の束 ＝ config.lots[k×(m)+j]。1,200枚なら 山1=0001/0002/0003、山2=0004/0005/0006 …
  冠野には各山を100枚ずつ数えて分けてもらう（合紙・帯への番号印字は確認中）

## カード面（2026-09-17凍結）
表: HeartCloak Project（Zen Kaku 7.5pt・金）／こころづて（Shippori Bold 16pt）／
　　こころを預かり届けます（Shippori 7.5pt・墨）／ふとした時に、こころを残してみませんか？（6.5pt・墨70%）
裏: 左列 QR 22mm＋short_id（Courier Bold 9pt）＋lot_no（金枠バッジ・Helvetica Bold 8pt）／
　　右列 説明4行（Shippori 6.5pt）＋協賛欄＋heartcloak.com（Zen Kaku 5.5pt・金）
- 協賛あり束: 金罫 → 「このカードは下記の協賛により作られました」 → ロゴ（50×7mm・ベクターPDFはそのまま埋め込み）
- 協賛なし束: 右下を約50×18mm空ける（運営が配布前に判子を押す余地）。URLは左列 lot 枠の下
- 文字だけの協賛面は作らない。β・作成日・罫線は刷らない

## 裏面のQR（2026-07-24確定／2026-09-16 ECC決着）
- QR実寸22mm（下限20・上限25）。**ECC Q・v5・37×37＝1マス0.595mm**（安全圏。危険域は0.4mm以下）
- クワイエットゾーン: 4モジュール分＝2.4mm以上の白地。実装は右列開始まで6mm・左5mm・上5mm・下は short_id まで2.7mm
- 配置: トリム端から5mm以上内側。白地に黒・単色。反転・背景への重ね・淡色インクは不可
- URL: `https://heartcloak.com/receive.html?room=<short_id>`（47文字・直焼き）。short_id は新30文字セット
  （g i l o s z 不使用）。エンジンが旧文字・桁違い・重複・件数不一致を検出したら生成を止める

## 色
- CMYK直指定。黒は K100。金 C15 M35 Y95 K15。朱 C0 M85 Y90 K5（今回未使用）。RGB演算子ゼロを生成後に確認
- 協賛ロゴ: ベクターPDF（DeviceN/CMYK可）はフォームXObjectとして埋め込み。PNG/JPG なら350dpi以上で配置
- 第1バッチはロゴ束を含むため4色印刷（4丁付けは1シート1ジョブ・面ごとに色数は分けられない）

## 技術（実装済み）
- Python 3 + reportlab + qrcode + pillow + pdfrw。フォントは Google Fonts 原本（Shippori Mincho R/B・
  Zen Kaku Gothic New）を初回に自動取得し、ReportLab が自動サブセットで埋め込む。fonts_subset.js は使わない
- QRはモジュール矩形の直描き（行ごとの連続区間をまとめてパス化）。画像貼り禁止
- 出力: 1バッチ=1PDF（400枚=200ページ・約1MB／2,000枚=1,000ページ・約5MB）＋照合CSV
  （c／sheet／k／lot_no／short_id／global_no／URL／sponsor／mono）
- 置き場: tools/print_engine/（公開リポジトリ）。**manifest.json・生成PDF・照合CSV はリポジトリに入れない**

## 運用手順（毎バッチ）
1. 事前チェック: `select lot_id, expires_at, created_at from bundles where lot_id in (...)` → 0行
2. 束を作る（SQL Editor・1本ずつ）: `select create_bundle_v2('0005', '2027-03-31 23:59:59+09', 100);`
   ※ create_bundle_v2(p_lot_id text, p_expires_at timestamptz, p_count int)。SQL Editor は auth.uid() が
   null のため operator 判定を素通りする（設計どおり）。short_id はトリガーで自動付与
3. `select count(*) … where short_id is null` → 0 を確認
4. マニフェスト書き出し（json_agg … order by b.lot_id, r.position）→ manifest.json（export_manifest.sql ④）
5. config.json の lots（束ごとの協賛・mono・url_pos）を並べる。400×m に応じて cards_per_stack=100×m
6. `python card_engine.py --manifest manifest.json --out batch_000N.pdf` → NGなら止まる
7. `--sheets 1` で1シート目だけ出し、コンビニ原寸100%で幅91mmと4面位置を確認
8. 入稿。納品後は各山を100枚ずつ束に分ける。lot_no・親QRはDBに既にある

## 冠野変数（2026-09-17時点）

- 印刷方式: **両面デジタル** → 決着（見当ズレ懸念なし・表を束ごとに変える余地あり）
- 折り軸（K3）: 版下同方向・刷版で調整 → 決着（ミラー無し）

- 数量を「400×5回」固定 → **400×m**（束ごとに協賛切替）。10丁は次回課題のまま
- 印刷ゲート（HANDOFF 2026-08-12）を反映: 本番束は印刷直前に新規生成し、既存在庫を流用しない
